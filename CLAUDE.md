# One Tiny Island: notes for coding sessions

A just-for-fun, procedural low-poly three.js island diorama (volcano, village, a windmill and wheat beds, a villager with a canoe, lagoon, wildlife and macaws, 8 weathers, day/night, boats, a galleon and friendly pirates) in **one self-contained HTML page**, deployed as a static site.

## Layout

- `index.html`: the whole app, in order:
  - `<head>` metadata (social tags, data: favicon) and one `<style>` block.
  - `<script id="boat-hull">`: readable hull builder `window.__islandBoatHull`, used by every boat.
  - `<script id="ships">`: readable plugin with the galleon and the pirate ship.
  - `<script id="farm">`: readable `window.__islandFarm` (`build`, `soil`, called by the bundle) and the `farm` plugin (windmill wheel, wheat, villager and canoe).
  - `<script id="parrots">`: readable `parrots` plugin (three pairs of red-and-blue macaws).
  - `<script id="sheep">`: readable `sheep` and `chickens` plugins (five sheep round the field, five hens in the village and fields, and the UFO that borrows a sheep each clear night).
  - one huge `<script>`: an esbuild-minified IIFE of three.js r187 plus the app. **No sources exist.**
  - `<script id="hints">`: one-time "Drag to look around" toast (`localStorage['oti-hint-drag']`). The only other stored key is the style, `oti-style`.
- Loading screen (`#loading`, before the scripts): bright clear-sky gradient, the logo (`img.ld-name`: a 1096 x 688 WebP with a transparent background, embedded as a `data:` URI, about 117 KB of base64 on one line: never print that line), the line "Shaping a tiny island…" and a progress bar (`.ld-bar`, two `<i>` fills). The bar is an estimate, not a measurement (`jx()` is one synchronous block): the first fill eases toward 95% over 8 s and the second sweeps to 100% when `done` is added. It animates only `transform` on HTML elements so the compositor keeps it moving while `jx()` blocks the main thread (about 1.5 s to build plus 1.3 s for the first frame's shader compiles under headless swiftshader). The build starts once the logo has decoded (`otiLg.decode()`, 250 ms at most, at the end of the bundle), so the logo is painted before the page blocks. The panel title (`img.tlogo` in `wf`) shows the same logo: its `src` is copied from `img.ld-name` when the panel is built (`otiTL`), falling back to the text "One Tiny Island"; with the logo, the title row is a light sky card so it reads on the dark panel.
- `scripts/screenshots.mjs`: Playwright generator for `docs/screenshots/*.jpg` (read its header).
- `docs/screenshots/`: README images; `hero.jpg` is also the page's social preview image (`og:image`).
- `docs/logo.png`: the logo with a transparent background (README header; the master the loading screen's WebP is made from). `docs/social-preview.jpg`: the logo on white, 1280 x 640, for the GitHub repository's social preview (uploaded by hand in the repository settings).
- `UI-GUIDELINES.md`: the UI system (tokens, type, components, accessibility, icons, voice). `THIRD-PARTY-NOTICES.md`: three.js (MIT), Material Symbols (Apache 2.0) and Octicons (MIT, the GitHub mark) licence texts.
- `_headers`: Cloudflare Pages caching and security headers. `README.md`, `LICENSE` (MIT), `.gitignore`.

## Golden rules

1. One self-contained file: no extra JS/CSS files, no CDN, no fonts, no images loaded by the page (the loading screen's logo and the favicon are `data:` URIs inside it).
2. Zero network requests at runtime (the one link out, "Source on GitHub" at the bottom of the panel, only opens a new tab when pressed). No build step: the repo root is the site.
3. Kid friendly: nobody gets hurt, nothing burns or sinks. Cannonballs always miss.
4. Keep `window.__island` (and `__island.ships`, `__island.farm`, `__island.parrots`) stable: the screenshot script, the README and people's consoles use it.
5. The page must load with a clean console (no errors, no warnings) and keep working without WebGL extras, sound or storage.
6. UI changes follow UI-GUIDELINES.md (and update it in the same commit).

## Editing the minified bundle

- Never reformat, re-minify or rewrite the big script. Change it with **exact string replacements that match exactly once**: count the anchor first (`grep -oF 'anchor' index.html | wc -l` must be 1), then use a short unique anchor with the Edit tool or a script that asserts `s.count(old) == 1`. Lines are hundreds of KB long: never print whole lines, use `grep -o '.\{80\}anchor.\{200\}'`.
- To read it, pretty-print a copy into a scratch dir (never into the repo):
  ```sh
  awk '/^<script>\(\(\)=>\{/{f=1} f{print} /^<\/script>/{if(f)exit}' index.html | sed '1s/^<script>//; $d' > /tmp/x/bundle.js
  prettier --parser babel /tmp/x/bundle.js > /tmp/x/bundle.pretty.js
  ```

- Surface detail (High only, all inside `Ri`, no textures): the fragment shader reads what a surface is from its vertex colour, height and slope and adds colour variation plus a height `otiBh` that `otiBump` turns into bump lighting after `<normal_fragment_maps>`. `Ri` option `detail`: terrain (`terrain: true`: grass mottling, sand ripples/pebbles, `otiRock` strata, path pebbles), `"rock"` (boulders, `otiRock`), `"veg"` (leaf dapples on green, bark streaks otherwise), `"grain"` (village and boats: grain down each face, thatch rows on warm sloped faces); `ji` picks `"veg"` for swaying instances and `"rock"` for the rest (coral gets none). GLSL helpers: `otiCell` (cellular), `otiN3` (3D value noise), `otiLod(k, fw)` (fades a detail of k cycles per unit before it gets smaller than a pixel: use it on every octave), `otiSp` (sand/snow mask for the sun glints added in the `<opaque_fragment>` hook). `vOP` is the un-swayed local position plus the instance offset, so patterns do not slide when the wind bends a tree or a boat moves. `Zt.otiDet.value` (1 High, 0 Low) is read **when the shader is compiled** and is part of the program cache key: Low compiles without any of this, and `setQuality` disposes the scene's materials so they recompile. New detail must stay in the existing programs (same options on materials that share one), so the program count does not move.

- Style (Classic / Toon, both tiers): `e.style` (`"classic"` or `"toon"`), read once at start-up from `localStorage['oti-style']` (try/catch, Classic without storage) and set by `setStyle` (panel: the Style segmented control `.seg.look`, buttons `otiLk`; console: `__island.setStyle`), which stores it. The flag is the shared uniform `Zt.otiToon` (set by `r()` and `setStyle`); like `otiDet` it is read **when a shader is compiled** and is part of `Ri`'s program cache key (`toon`), so `setStyle` disposes the scene's patched materials (the same traverse as `setQuality`) and they recompile: the program count is the same in both styles. Toon means:

The three.js Lambert chunk (`RE_Direct_Lambert`) has an `#ifdef OTI_TOON` that turns `dotNL` into three bands (0, 0.6, 1); only `Ri` materials get the define (the few plain Lambert materials, e.g. the turtles, stay smooth). After `<color_fragment>` the albedo is pushed away from its luminance (x1.28) and brightened 5%.
  - `otiDet` is 0 (no surface detail, gloss or glints on High), and the sun's `shadow.intensity` is 0.8 (1 in Classic).
  - High only, in the composite (`otiPo.ms[2]`, same single program, uniform branch on `uTn.x`; `otiTnU` fills `uTn` = (toon, night, outline offset in px, 0) and, in Toon, `uPj`/`uFg`/`uCY`, which are otherwise only set while contact shading runs): a saturation and gamma lift that fades at night, contact shading at 60%, glow x1.25, vignette x0.6, and **outlines** from the depth texture (relative depth jump or depth Laplacian over 1.2 px x `max(1, 0.75 pixelRatio)`), darkening to 28% of the colour, faded out between 70 and 230 units and by the fog and height mist. The composite now gets the texel size in `uT`. Low, and High with the glow shed (`otiPoOff`), have no outlines.
  - Water, sky, clouds, lava and unlit (`MeshBasicMaterial`) meshes keep their own shaders in both styles.
- Surface look (High, `Ri`): sand is calm (each sand pixel pulled about 75% toward the mid of `sand`/`sand2`, so the per-vertex blotches mostly vanish) with soft asymmetric ripples and a damp band near the sea; rock (`otiRock`) has only soft straight strata, subtle cracks and lichen; rock near the waterline is darker and glossy (`otiWetR`/`otiWetC`, terrain and boulders); grass has broad dry/lush patches and clumps; foliage has low-frequency sunny/shaded clumps; thatch has bold bands with bundle tints and warm wooden walls get vertical boards (`"grain"`). The grass, foliage, thatch-edge and board terms fade out at night (`otiDN = 1 - smoothstep(.15,.6,uNight)`) so lamp-lit surfaces keep their brightness.
- Gloss (High, in `Ri`): the detail blocks also set `otiGl` (wet-sand band at the waterline, leaves, anything rain-wet); the `<opaque_fragment>` hook adds a sun highlight and a sky-coloured grazing reflection from the bumped normal.
- Beaches (`Yu`, both tiers): outside the island outline the ground follows `otiBe`: a gentle beach slope and a shallow shelf (width varies round the coast), then the drop-off to `qu`. The distance it works from is the smooth minimum of the distance to the outline, to an apron round the north mesa (`wi`) and to an apron round the volcano's foot (`he`), which is what gives those two a beach instead of a plunge. Sand islets (`Nx`) end in a beach slope too. In `Qu` the lattice thresholds were tightened (cells wholly under water use the coarser sizes) to pay for part of the extra shallow ground. Depth on the boat lanes: at least 2.7 at r 70, 5.8 at r 73, 8.7 at r 79.
- Cliffs (`Qu`, both tiers): steep sand/dune/shallow-seabed faces are coloured as rock, steep faces (`X > .6`) take their colour per corner from the corner's own height and slope, and keep part of the smoothed normal (`otiS`), so cliff and islet sides do not break into stretched sand-and-rock slivers.
- Rounder shapes (High): every vegetation builder (`zx` palm, `Hx` broadleaf, `Gx` conifer, `kx` bush, `Vx` boulder), the corals (`otiQxH`, rngs `Ze(4253)`..`Ze(4255)`), the gulls, fish, turtles (`Ze(4250)`) and dolphins in `mf`, the parrots (through `kit.highShape`), the round huts, the spring rocks and clumps, the flying Santa and the snowman's Santa hat first build their Low geometry exactly as before (so `ve`, `otiR`, `ke` draw the same sequence; `zx` records its 32 `ve()` draws and replays them), and register a High builder with `otiHQR`. `otiHQS(high)` swaps `mesh.geometry` both ways (disposing the outgoing one, resetting instanced bounds); High geometry is built lazily on the first High (own rngs `Ze(4244)`..`Ze(4248)`) and kept in JS. It runs right after the plugins start (so parrots always plan from the Low canopy) and in `setQuality`. `otiHSm(g, crease)` smooths normals (numeric position hash). The village static mesh `ze` is built by `otiHVM` from recorded pieces (`otiHVP`), and `otiHVB` splices High pieces (round huts with 20 sides and a domed thatch, lumpy spring rocks, flat-shaded because the `"grain"` detail builds its frame from the normal; smooth green clumps) into it; farm beds, lighthouse and square-hut roofs are untouched. Building High geometry creates three.js objects whose UUIDs draw from `Math.random`, so a harness that seeds it drifts after start-up (reseed after load). Grass and terrain still follow the start-up quality only.
- Grass (`cf`): `otiXx()` is the High tuft (5 curved blades); `otiGX` are the extra High tufts from a jittered grid with their own rng (`Ze(4711)`/`Ze(4712)`; acceptance scaled by 0.93 to make room for the farm), appended after the original 950 in the same instanced mesh. Low keeps `Xx()` and the original count. Do not draw from `ve` for new placements: it would move everything placed after.
- Start-up hand-off (end of the bundle): `Qx` sets `otiLdF`, which the first completed `otiFrame` calls once (the first frame is drawn inside `jx`, by its closing `bt()`). It adds `done` to `#loading` on the next `requestAnimationFrame` (after the slow first frames, when the scene is on screen), with a 300 ms `setTimeout` fallback because the headless recipe and `scripts/screenshots.mjs` drop or hold rAF callbacks and a tab hidden mid-build gets no rAF; the loader is removed 700 ms later. If `jx` throws or returns without drawing (no WebGL), the loader is removed at once and only the failure screen shows.
- Frame (`otiFrame(force)` in `jx`, called by the loop and by `__island.step`): resets `renderer.info` (autoReset is off, so `info()` reports whole-frame totals), runs `otiMirror`, then on High renders the scene into the scene target `otiSc` and runs `otiPostRun`, which draws the canvas; on Low (or with the glow shed) it renders the scene straight to the canvas as before.
  - `otiScGet` (High): the scene target `otiSc.rt`, drawing-buffer size, 4x MSAA, `internalFormat "RGBA8"` with an sRGB texture and a `DepthTexture`, flagged `isXRRenderTarget` like `otiMi.rt` so the scene renders with the **same programs** as the canvas (tone-mapped and sRGB-encoded). `__useRenderToTexture` is forced false every frame (`setSize` drops it), so colour and depth always resolve through the explicit blit and the depth texture is valid on every device. Sky dome and clouds write no depth (sky pixels read 1.0).
  - `otiPostRun(sc)` (High): runs the depth effects (`otiEfRun`), then the bright-pass on `sc.rt.texture` plus three downsamples and three additive upsamples over four 8-bit targets (1/2 to 1/16), then **one opaque composite quad** (`otiPo.ms[2]`, one program) draws the canvas: scene, contact shading, glow, vignette. Threshold and strength follow `uNight` and snow cover. The scene render itself is untouched (display-space glow, not HDR). State in `otiPo`; freed on Low.
  - `otiMirror` (High): planar water reflection. Mirrored camera about y = 0 with an oblique near plane, half-size target `otiMi.rt`, flagged `isXRRenderTarget` with an sRGB texture so the pass uses the **same programs** as the canvas (without that every material compiles a second variant); the water shader (`OTI_REFL` define, uniforms `otiRT`/`otiRM`/`otiRK`) undoes sRGB and the tone curve before mixing it into its sky reflection. Hidden in the pass: water, rim wall, sky dome, clouds (they read as white patches lying on the sea), rain, snow, wildlife, shadowless plants, anything with `userData.otiNoMirror` (set once, before the first pass builds the list) and **every additive material** (they write alpha 1 over empty sky, which shows as black blocks); the seabed is skipped through the terrain's `onBeforeShadow` draw range. Skipped when `otiRK` is 0 (rough sea, rain, ice, camera steep or very low) and, in the live loop, on shadow-map frames; `step` always renders it.
  - Depth effects (High, `otiEfRun(sc, P)`, all off and freed when `otiEfOff` is set or their `otiFx` strength is 0; strengths through `__island.setEffects`):
    - Contact shading (`otiAoRun`, state `otiEf`): two half-res passes. SAO-style estimate from the depth texture (normals from depth, 10 golden-angle taps, 4x4 Bayer rotation, radius `clamp(0.01 z, 0.45, 1.6)`), then a depth-aware 4x4 blur that also stores the half-res depth; the composite (`otiAo`) upsamples it plane-aware and multiplies by `1 - 0.45 ao`, faded by the scene fog and height mist, on bright pixels and at night. Level ground near sea level gets none, and taps below the waterline do not occlude (no dark band along the shore). The river writes no depth, so it gets none.
  - Shedding: when the adaptive check finds the page slow it sets `otiMiOff` (reflections) first, then `otiEfOff` (depth effects), then lowers the pixel ratio, then sets `otiPoOff` (glow, back to the direct-to-canvas path, everything freed); `setQuality` clears all three. `setAdaptiveResolution(false)` freezes all of it.

- Camera (`l` = OrbitControls in `jx`): pan over the ground (right-drag, two fingers, arrows on the focused canvas), tilt 0.02–1.5 rad, distance `max(6, q*.03)`–`q*1.7`, pivot within 70 of the default `(-1, 2.5, 3)` (`l.cursor`, `l.maxTargetRadius`). `otiCam` (set by user input, cleared by `setCamera`/`reset`) makes the pivot ride the ground (`max(te,0)+otiCamK`) and eases the camera up to terrain + 9.5 over land (`otiCamH`/`otiCamU`); the hard floor at terrain + 3.5 applies to every camera. The opening (and reset) view sits at `otiHD = q * (aspect < 1.2 ? .82 : .7)`, closer than the framing distance `q` that the zoom limits and `setCamera`'s distScale are relative to. `otiHome` is the reset view (double-click/double-tap via `otiTap*`, Home key). Scripted cameras are unaffected.

## Plugin hook and `kit`

Also `worldRadius` (`De`), `scene`, `camera`, `controls`, `state`, `toast(msg)`, `audio()` (the `ul` instance) and `farm` (`uf`'s `otiFarm`): `material` (the boats' `St`), `canoe` (`{mesh, moor, busy}`), `jetty` (`J0`, `JE`, `dir`, `deck`, `len`, `width`), `huts`, `bridges`, `bungalows`, `fishing` (`{x, z, drift}`), `props` (well and campfire as `[x, z, r]`), `plaza`, `paths` (`to`), `river` (`Vn[0].pts`), `riverAt(u)`, `riverSurface(u)` (the water height `_f` bakes), `riverWidth(u)`; and `forest`: the broadleaf trees' InstancedMesh (perch trees for the parrots). `highShape(mesh, build)` registers a High geometry builder for a plugin mesh (`otiHQR`; built lazily, swapped by the Quality setting) and `smoothNormals(geometry, crease)` is `otiHSm`.

## Boats and ships

- `__islandBoatHull(T, length, beam, height, hullColor, deckColor, options)`: bow +x, keel at -h/2, deck at +h/2; `geometry.userData` has `deckAt`, `sheerAt`, `sideAt` for seating masts and gun ports.
- Ships plugin: galleon lane r 79 (outer, angle increasing), pirate lane r 73 (inner, the other way round); the sailboat circles at r 70, sand spits reach r 67.5, the hard rim is r 86. Ships stay away (or leave) when `ice > 0.2`, `sea > 0.8`, `calmK < 0.7` or `wind > 0.8`.
- Encounter phases: `approach` → `volley` → `escape` → `peel`. Every shot aims well ahead of the bow or astern of the target and is checked against both hulls; `state().minMiss` must stay above `hullRadius`, and a landing inside a hull radius logs a console warning (treat it as a failure).
- The pirate main sail carries one flat skull badge per face; `sailSurfaceX()` (next to `sailStrip()`) gives the sail's real surface so the badges sit a hair off it.
- The ship hulls use the village and boats' material options (`snow: 1, wet: 1, detail: 'grain'`): wood grain on High and the same program as the other boats.
- Everything is pooled: no per-frame allocations, at most 8 extra draw calls while ships are out, 0 while away.

## Farm (`<script id="farm">`)

- Field layout (field-local, +lz downhill toward the default camera): four wheat beds round a cross-shaped lane, the windmill at its centre (wheel facing field angle 0.3), jars by the trestle, the scarecrow at the west end, the field hut east of the rim. Beds are seeded superellipses (`SHAPES`, `rho`, `halfWidth`) with ridged soil and a low skirt; `soil(lx, lz)` gives the terrain halo. Every corner stays 0.5 inside the lop-sided rim.
- `build(T)` returns tinted, world-placed, non-indexed geometries (position, normal, color) that `uf` merges into its static mesh: beds, trestle, jars. Wrapped in a try with a console warning; without `__islandFarm` the page loads with an empty field.
- Windmill wheel (one mesh): eases (`1 - exp(-0.8 dt)`) toward `0.25 + 3.2 wind` rad/s, at most 4.5, 0.05 under ice.
- Wheat (one InstancedMesh, no shadow, `otiNoMirror`, on the grass program: `weatherMaterial(Lambert{vertexColors, DoubleSide}, {detail: 'veg', sway})`, instance colours set before the first render). Per bed a phase 0..1: sown < 0.06 < sprouts < 0.16 < growing < 0.5 < ripening < 0.7 < ripe < 0.88 < harvest sweep (cut across the bed) < 0.96 < stubble. Rates (x sqrt(speed)): growth `0.006 (0.35 + 1.4 moisture)`, ripening `0.006 (0.5 + 0.7 (1 - rain))`, harvest 0.12 over 14 s; nothing grows with snow cover > 0.3 or ice > 0.2. Moisture rises quickly with rain and dries in about 5 minutes. A dry cycle is about 5 minutes, a rainy one about 2.5. A bed's instances are rewritten only when its look changes by a step, at most 10 times a second.
- The wheel and the villager use a copy of the boats' material (`onBeforeCompile` and `customProgramCacheKey` copied, so the same program) with `shadowSide = BackSide`: the shared shadow depth material only re-picks its program when it switches between instanced and plain meshes, and with `St` itself the wheel (right after the instanced wildlife) compiled a new double-sided depth program. Thin parts (sails, paddle blade) are two-layered so they still cast from both sides. Keep anything new that casts shadows on that copy.
- Canoe: the dinghy `Ot` (same hull builder and triangle count). While `kit.farm.canoe.busy` the plugin owns its transform; otherwise `uf` bobs it at its mooring `Bt`.
- Villager (one rigid mesh, `matrixAutoUpdate` off). Phases: `home` (hidden) → `walkOut` (hut door → jetty) → `board` → `toLanding` (slides out of the berth keeping its heading, backs onto the beach) → `disembark` → `lift` → `portage` (canoe upside down on the shoulders: jetty root, `to[3]`, round the north of the well, `to[0]`, round the field's east edge, `to[2]` to the bank below the upstream footbridge) → `launch` → `embark` → `river` (smoothed centre line, rides `riverSurface`, ducks under the downstream footbridge) → `lagoon` (the long way round from the mouth, never across the jetty) → back to `disembark`. Going home: `toMooring` (from a short window after the branch point near the end of the lap) → `berth` (backs in, heading fixed) → `unboard` → `walkHome`; called home after the window, it lands and takes `reMoor` (backs off the beach) into `toMooring`. Speeds: walk 1.3, carry 1.2, river 1.8, lagoon 1.2 (the stroke surge averages out). A loop takes about 2 minutes.
- Rules: out while `night < 0.25`, `rain < 0.5`, `calmK > 0.78`, `snowCover < 0.2`, `ice < 0.1`; turned back by `night > 0.4`, `rain > 0.66`, `calmK < 0.62`, `snowCover > 0.38`, `ice > 0.2` (finishes the leg down to the lagoon, then moors). A carry is only started (morning start, branch point, landing) if the rest of the loop and the way home fit before dusk (`night` 0.45, from the bundle's sun curve, the clock and `state.speed`; unlimited when the day cycle is paused). In time-lapse the villager hurries up to 3x; above that a loop never fits and they stay home. Ice or snow cover over 0.5 snaps them home (canoe back at its mooring).
- API `__island.farm`: `state()` (`beds[{phase, stage, height}]`, `moisture`, `windmill{speed, angle}`, `villager{phase, x, y, z, progress, afloat, visible}`, `canoe{x, y, z, busy}`), `setGrowth(p | [p0..p3])`, `setMoisture(m)`, `setVillager(phase, progress)` (bad input is ignored), `check()` (samples every leg: walker and carried canoe against huts and props, ground under the walk, river banks, footbridge headroom, lagoon depth, jetty, bungalows, fishing boat, berth manoeuvres; worst values with `where`, `ok`).
- Draw calls: wheel, wheat, villager (+ wheel and villager in the shadow pass and the reflection); 0 for the villager at night. Nothing is allocated per frame.

## Wildlife (`mf`)

- Both tiers move the same way; only the shapes differ. Nothing is allocated per frame; the update draws only from its own rng `Ze(4261)` (dolphins still use `Xe`).
- Fish (40, three schools by `index % 3`): each school centre wanders on fixed sine curves round its `otiFS` base; each fish steers toward its slot in the school (turned to the school's heading), keeps 0.45 from its schoolmates, turns at most 2.4 rad/s, eases its speed, banks into turns (Euler `YZX` in `otiE`) and pitches with depth. State in `otiFP` (x, y, z, heading, speed, turn rate). A look-ahead of 0.9 turns it back toward its base before water shallower than -0.7. Depth: at least 0.2 over the seabed and below -0.2. A school bolts (scatters outward at 2.8 for 1.3 to 1.8 s, 7 s cool-down) every 25 to 65 s, or when the moving canoe comes within 4.5 of its centre. Tail beat in the vertex shader (`otiFiS` on the fish `MeshBasicMaterial`): model x < -0.04 swings sideways, phase from `gl_InstanceID`.
- Turtles (2): wander between random waypoints within 8 of `($t.x - 1, $t.z)` deeper than -1.3, kept 3 from the bungalows and the jetty end (`otiAv`); turn at 0.45 rad/s (1.2 when steering off shallows seen 1.8 ahead, or away from a stilt). Speed surges on each front-flipper downstroke (`-cos(uTime 2.4 + 2.1 k)`, the same clock as the shader). Every 40 to 70 s one rises to the surface (`rr` minus 0.24), holds 2 to 3 s nose up, then dives; never closer than 0.22 to the seabed. Flipper stroke in the vertex shader (`otiTuS` on `otiTu`'s Lambert): vertices outside the shell ellipse (x 0.68, z 0.56), between x -0.68 and 0.6, rotate about the shell edge (front 0.55 rad, rear 0.22).
- Both patched materials keep their own single program, so the program count does not move.

## Parrots (`<script id="parrots">`)

- One InstancedMesh of 6 birds (three pairs, 40 triangles each, 143 on High from `buildBirdHigh` through `kit.highShape`: 8-sided rings, a two-part beak, three blue fingers per wing, a red-then-blue tail, same fold layout; `SIZE` 1.3) on the gulls' program (`weatherMaterial(Lambert{vertexColors, DoubleSide}, {snow: 0, wet: 0, flap: true})`), no instance colours, `castShadow = false`, `frustumCulled = false`, `userData.otiNoMirror`: one draw call. A five-sided barrel (tail base, plump shoulders, raised round head with pale cheeks), a short charcoal beak hooked down, broad blunt wings (red coverts, bright blue flight feathers), a long blunt tail half red, half blue. Flat colours per triangle (blending red into blue makes purple): **red and blue only, no yellow, no green**.
- Bird frame: wingspan along x, **head along local +z** (unlike the gulls), y up; yaw `atan2(dx, dz)`, Euler YXZ (yaw, pitch, then roll about the body). Perched: pitched up 0.55 with x scale 0.4 of the bird's, the signal for the fold in `Ri` (wings on the back, head level, no flap, body at full width); taking off and landing ease it to 1 and back over 0.7 s. In flight the yaw turns the same way once started (no wrap flip).
- Perches: up to 8 broadleaf treetops (the canopy's highest vertex through each instance matrix), dense forest (3+ trees within 6), at least 12 apart, more than 10 from the plaza and the field, off the volcano. The first five are the treetops nearest the home camera (as the page opens) that it can see: inside the frame, the line from a bird's head to the camera clears the ground and every shadow-casting vegetation instance's bounding sphere. A pair sits side by side, 1 apart, closed up to 0.8 or 0.6 where a neighbouring crown would touch a slot (a perch where even 0.6 touches is skipped). `Ze(7171)` breaks ties.
- Arcs: one curve per pair of perches 10 to 35 apart, flown either way (the return trip mirrors the bulge), so links are always two-way. A hump keeps the arc line 1.6 over the treetops (height field of tops within 3.1) and ground for the leader and the mate on either side (0.6 aside, 0.3 higher; birds are drawn 0.5 above the line, so `check()` reports at least 2.1); an arc whose first or last 2.8 comes within 0.15 of a neighbouring crown is dropped. Then perches without links are dropped, and, while more than four remain, perches with a single link. Pairs start on free perches with a way out. Flight time 1.15 x distance / 4.2 + 1.6 s; the mate follows 0.5 s behind.
- Cycle per pair: perched 10 to 25 s (a look-around wiggle), then, in fair weather (`rain < 0.4`, `night < 0.5`, `wind < 0.8`, `snow < 0.3`; grounded above 0.5 / 0.6 / 0.9 / 0.4), the last 2.2 s settle the wiggle and turn the pair on the perch toward the next tree (at most 1.3 rad/s) before it takes off. Half way through a flight the pair reads where `kit.camera` is and lands facing it. A flight in progress always lands. Perched birds stay visible at night and in rain.
- Start-up: about 9 ms headless (perch choice with cheap tests first, crowns pre-filtered per perch, a height field for the humps).
- API `__island.parrots`: `state()` (`fair`, `birds[{phase, x, y, z, yaw}]`, `pairs[{phase, from, to, t}]`, `perches` as `[x, y, z, seenFromHome]`), `fly(pair?)` (undefined or an integer index; the pair leaves after settling, weather or not; otherwise a reason string), `check()` (`worstClearance` over the treetops, `endCrownClear` at take-off and landing, `slotCrownClear`, perch `degrees`, `isolated`, `singleExit`, `oneWay`, `ok`). With too few trees the plugin still publishes `state` / `fly` / `check` saying so.

## Sheep, hens and the UFO (`<script id="sheep">`)

- One IIFE pushes two factories: `sheep` (does all the work, publishes `__island.sheep`) and `chickens` (only publishes `__island.chickens`, the API the sheep factory left in `henApi`). Sheep and hens share the one CPU-posed mesh: sheep first, then hens, each from its kind's template (`SHEEP`/`HEN` spec: `size`, `neck`, `hips`, `swing`, `drop`; hens also `wing`). Template parts: 0 body, 1 head, 2..5 legs, 6/7 right/left wing; colour roles 1/2 take each hen's plumage from `HENS`. Hens add no draw call.

- Pasture (start-up, own rng `kit.rng(5150)`): a 0.5 grid within `RAD = max(a, b) + 5` of the field centre, inside the ellipse `a + 4.2` x `b + 4.2` (field-local), off the wheat beds (`__islandFarm.soil < 0.02`), on dry gentle grass (`te > 0.8`, slope < 0.32), and clear of the huts, the field hut, props, bungalows, bridges, the plaza, the scarecrow, the windmill (1.9 round the field centre), the river (`riverAt` + width + 1.2), the villager's walks (1.1 round `__islandFarm.layout().tracks`, every 0.4 of `walkHome` and `portage`) and the trunks of every shadow-casting vegetation instance near the field. Five homes at least 2.6 apart, preferring cells seen from the opening camera with room round them; each sheep roams the cells within 2.6 of its home. `__islandFarm.layout()` (added for this) returns `{field, hut, tracks, man}`, or null before `build`.
- One plain `Mesh` (+ its shadow, `otiNoMirror`, fixed bounding sphere) on a copy of `kit.farm.material` set up like the villager's (same program). The CPU poses all five sheep into one preallocated buffer every frame from a template (`buildSheep(high)`: parts 0 body, 1 head about `NECK`, 2..5 legs about `HIPS`; 116 triangles on Low, 252 on High; `SIZE` 1.35); a quality switch rebuilds the template (the only allocation). Head along local +z, yaw `atan2(dx, dz)`.
- Hens (5, `HEN.size` 1.2, about 180 triangles on Low and 350 on High): ground is a 0.5 grid (`henGrid`, `henOK`) within 12 of the plaza, round the field (ellipse `a + 3` x `b + 3`) and within 4.5 of the line between them, dry (`te > 0.45`), slope < 0.5, clear of huts (+0.45), the field hut, props, bungalows, bridges, the scarecrow, the windmill, tree trunks (`max(0.45, 0.3 x bounding radius)`) and the river. Wheat beds are allowed. Homes: three within 8 of the plaza, two by the field; each roosts on the free cell nearest the door of the hut (or the field hut) nearest its home. Every move is a straight line checked every 0.25 (`henPath`) and kept 1 from the sheep and 0.45 from the other hens. Phases: `peck` (the bird tips forward 0.45 about the hips, quick head bursts), `look`, `walk` (0.5), `run` (1.6 to 1.8, wings flapping; now and then, or away from the villager when they come within 1.8: `__islandFarm.layout().man`), `roost` (at `night > 0.45`, legs of up to 3 toward the roost, side-stepping what is in the way; sits where it gets stuck) and `sit` (until `night < 0.3`).
- Sheep behaviour: graze 4 to 12 s (head down, nibbling), sometimes look up 2 to 4.5 s, then walk 0.35 (turning at most 1.5 rad/s) to a free cell 0.7 to 2.6 away (1.2 from the others and their targets). Lie down when `night > 0.55`, get up below 0.35.
- UFO: hull (lathed saucer, glass dome, 10 chasing rim bulbs; `MeshBasicMaterial({vertexColors})` with normals on the geometry, so it shares the program of the village's basic vertex-coloured mesh; `otiNoMirror`, since the mirror pass would compile a flipped variant) and beam (open double cone + ground glow, additive vertex colours, `forceSinglePass` so the double-sided transparent pass is one program, `otiNoMirror`). Both hidden by day: 0 draw calls at load, 2 while it flies, and one program (the beam's) compiled on its first night.
- Visit: `away` → `arrive` (6 s, eases in from 75 out and 45 up toward the sea side to hover 7.5 over the sheep) → `beamUp` (5.5 s: beam fades in, the sheep floats up turning, legs paddling, and shrinks into the hatch) → `leave` (3.2 s, accelerates up and away) → `waiting` → `arrive` over the sheep's home → `beamDown` (sets it down on its own spot) → `leave` → `away`. Once a night (`visitedTonight`, reset when `night < 0.3`) when `night > 0.7`, `snowCover < 0.1`, `snow < 0.05`, `ice < 0.2`, and the round trip fits before dawn (the farm's `nightAt` curve, `state.hours`, `speed`; it hurries up to 3x in time-lapse like the villager). It takes the sheep best seen from the camera. It comes back when dawn (`night < 0.5`) is less than one trip plus 8 s away, or after 45 s when the day cycle is paused. If `night` drops below 0.2 mid-visit (`setTime`), the sheep snaps home and the saucer hides: the sheep always comes back.
- API `__island.chickens`: `state()` (`chickens[{phase, x, y, z, yaw, home, roost}]`), `scatter()` (every hen that is up dashes off; returns how many), `check()` (`cells`, `worstClearance`, `offGround`, `nan`, `ok`).
- API `__island.sheep`: `state()` (`sheep[{phase, x, y, z, yaw, home, away}]`, `ufo{phase, x, y, z, sheep, beam}`, `visitedTonight`), `summon()` (now, at night, weather or not; else a reason), `bringBack()` (while `waiting`), `check()` (`cells`, `roam`, `worstClearance`, `badCells`, `offPasture`, `nan`, `ok`).

- Quality at start-up: Low only on a coarse pointer with at most 4 cores that is not an iPhone, iPad or iPod (`/iP(hone|ad|od)/` in the user agent, or `MacIntel` with touch points: iPadOS); everything else starts on High.

- Screenshots: `node scripts/screenshots.mjs [--only a,b] [--out DIR]` (about 3 minutes). Look at every image you regenerate; keep the nine under about 3 MB total.
